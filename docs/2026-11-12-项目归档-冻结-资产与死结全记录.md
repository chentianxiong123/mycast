## 1. 项目是什么

**MyCast 家庭影院**：手机/桌面投屏到电视的中继。

核心价值链：**B站 / 盗版影视站 → 拿到视频流 → DLNA 投到电视**。

- **B站**：解析 DASH 流，续期 URL，投屏（已验证）
- **盗版站**：嗅探（sniff）提取集数 → 拿流（m3u8/mp4）→ 投屏
- **手机端**：Android 自写壳（纯 aapt2，真机跑通）
- **桌面端**：wails3 原生窗口（WebKitGTK）

## 3. 冻结的原因：桌面套皮浏览器的死结

方向 E 想做"主窗口当套皮浏览器，搜索真跳搜索引擎，影视页自动清洗归一化"。想法没错，但 wails3 + WebKitGTK 这条技术栈有一连串硬限制：

### 死结清单

1. **改手机 UA**：wails3 v3.1.0 Linux（WebKitGTK）**没有公开 UA 字段**，要 fork 改源码 `webkit_settings_set_user_agent_with_application_details` 那行。
   - 详见 `docs/2026-11-10-改手机UA-wails3linux没有公开字段.md`

2. **target=_blank 点击跳转无反应**：wails3 没连 WebKitGTK 的 `create` 信号，百度结果默认 `target=_blank` 触发新窗口请求 → 被静默丢弃 → 点击没反应。
   - 前端绕过：注入 JS 把 `target=_blank` 转 `_self`（已做，但治标）
   - 根本解：fork wails3 连 `create` 信号
   - 详见 `docs/2026-11-10-wails3套皮浏览器点击跳转无反应排查.md`

3. **主窗口跨域导航**：从本地 `/ui` 用前端 `location.href` 导航到外部站**不生效**，必须 Go 侧 `mainWin.SetURL()`（走 `webkit_web_view_load_uri`）。
   - 已加 `Nav` 桥 + `/api/nav` 路由

4. **注入时机**：`SetURL` 跳转后 `events.Linux.WindowLoadFinished` 钩子**不触发** → injectJS 丢失。
   - demo 用 `JS:` 字段（页面加载自动注入）能工作，但只对起始页；导航到新页面后不重新注入。
   - 要每次导航都注入，得 fork wails3 连 `load-changed` 信号每次 `ExecJS`。

5. **裸 WebKitGTK 壳白屏**：脱离 wails3 写纯 CGo WebKitGTK 浏览器，编译能过但**白屏**（GPU/DMABUF 渲染问题，需 `WEBKIT_DISABLE_COMPOSITING_MODE=1` 一类标志，未深究）。

### 根本判断

这些不是 bug，是 **wails3 桌面端对"套皮浏览器"场景的支持不足**。要做真正的套皮浏览器，wails3 这层封装碍事，得 fork 改源码，或换技术栈（CEF / Tauri / 纯 WebKitGTK fork）。投入产出不划算，所以冻结。

## 4. 如果以后重启，从哪接

### 路线 A：放弃桌面套皮浏览器，只做投屏中继

桌面端退回"主窗口 + 影视库 + 搜索"，不要套皮浏览器。集数提取用纯 HTTP（`sniff.Extract` 已能对付大部分站），JS 反爬站用 WebView 兜底渲染回传（`renderPage` 已有）。这条路**已经能用**，只是没有"点搜索结果直接变成套皮浏览器"的体验。

### 路线 B：换技术栈做套皮浏览器

- **Tauri**（Rust + 系统 WebView）：Linux 用 WebKitGTK，同样的 UA/create 限制
- **CEF**（Chromium Embedded）：完整浏览器能力，无 WebKitGTK 的坑，但体积大（~200MB）
- **fork wails3**：连 `create`/`load-changed`/UA，最省事但绑死 wails3

### 路线 C：继续 Android 优先

Android 壳（`android/`）是自写的，没有 wails3 的坑，`AndroidOptions.UserAgent` 直接能改。把套皮浏览器体验在 Android 上做透，桌面端保持投屏中继。
