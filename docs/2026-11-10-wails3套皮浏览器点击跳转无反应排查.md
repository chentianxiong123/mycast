# wails3 套皮浏览器点击链接跳转无反应排查

## 背景

在做 MyCast 方向 E：主窗口当套皮浏览器，搜索真跳搜索引擎，影视页自动清洗归一化。结果发现主窗口真跳百度后，点百度结果里的站链接跳不动——只留百度域，其他站点了没反应，连百度自家子产品都不跳。以为是 mycast 的问题，开了个最小 wails3 套皮浏览器 demo 复现，demo 也跳不了。

## 问题现象

- wails3 WebKitGTK 主窗口加载百度，**点击结果里的站链接（跨站）没反应**，窗口不动
- 地址栏手动输 URL → 能跳
- 复制链接再粘贴到地址栏 → 能跳
- 只有「点击链接」这个动作没反应

## 排查过程

### 先怀疑 wails3 拦了导航

翻了 wails3 v3.1.0 源码（`linux_cgo_gtk3.go`），看它连接的 WebKitGTK 信号：

```
grep signal_connect linux_cgo_gtk3.go
→ delete-event / focus-out-event / configure-event / load-changed
```

**没连 `decide-policy`、没连 `navigation-policy`、也没连 `create`**。所以 wails3 本身没挂导航决策拦截。这条路排除。

### 怀疑 sandbox 拦跨站导航

WebKitGTK 2.54 默认开 web-process sandbox（bwrap）。看到进程里有 `bwrap --args ... WebKitWebProcess`，怀疑 sandbox 拦了点击导航。用 `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1` 禁用 sandbox 重启 demo，`bwrap` 前缀确实消失了（WebProcess 直接跑）——但点击照样跳不了。

**这条路也排除**：sandbox 拦的是 WebProcess 内的系统调用（文件/子资源），顶层导航是 UI process 发起的，不受 sandbox 影响。禁用 sandbox 是红鲱鱼。

### 真正根因：target=_blank + wails3 没连 create 信号

重新对照「能跳 vs 不能跳」的差异：

| 动作 | 走的路径 | 结果 |
|------|---------|------|
| 地址栏输 URL | `webkit_web_view_load_uri()` 当前窗口 | ✅ 能跳 |
| 点击 `target=_self` 链接 | 当前窗口导航 | ✅ 能跳 |
| 点击 `target=_blank` 链接 | 触发新窗口请求（WebKitGTK `create` 信号） | ❌ 没反应 |

百度搜索结果默认全是 `target=_blank`（新标签打开）。点击这类链接，WebKitGTK 发 `create` 信号请求开新 webview——**wails3 没连这个信号，新窗口请求没人处理 → 直接被丢弃 → 看起来就是「点了没反应」**。地址栏是当前窗口 `load_uri`，不走 create，所以能跳。这完美解释了现象。

## 解决方案

注入 JS 把页面里的 `target=_blank` 全转成当前窗口（`_self`），并在 DOM 变化时持续修正（百度会动态插结果）：

```js
var fixTarget = function(){
  document.querySelectorAll('a[target="_blank"]').forEach(function(a){ a.removeAttribute('target'); });
};
fixTarget();
new MutationObserver(fixTarget).observe(document, {childList:true, subtree:true});
```

加到 demo 的注入 JS 里，重启 demo —— **随便跳了**。验证根因正确。

## 坑与教训

- **点击没反应 ≠ 导航被拦**：先分清「当前窗口导航」和「新窗口请求」两条路径。`target=_blank` / `window.open` 走新窗口请求，`load_uri` / `target=_self` 走当前窗口。套皮浏览器必须处理新窗口请求。
- **sandbox 是红鲱鱼**：看到 bwrap 就往 sandbox 上想，浪费一轮。禁用 sandbox 验证（`WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1`）能快速排除，但顶层导航本来就不归 sandbox 管。
- **wails3 不处理新窗口**：wails3 v3.1.0 Linux 没连 WebKitGTK `create` 信号，`target=_blank` / `window.open` 会被静默丢弃。做套皮浏览器要么前端把 `target=_blank` 转 `_self`，要么 fork wails3 自己连 `create` 信号。
- **最可控的复现是最小 demo**：mycast 主窗口一堆逻辑，怀疑点太多。开个 50 行的 wails3 demo 一跑，现象一致，排查范围立刻收窄。

## 遗留

- demo 注入 JS 转 `_self` 是前端绕过；根本解法是 fork wails3 连 `create` 信号，把新窗口请求转成当前窗口导航（对用户无感）。MyCast 方向 E 正式实现时要决定走哪条。
- 这条和 MyCast 方向 E 的关系：方向 E 主窗口当套皮浏览器，必须解决 `target=_blank`，否则点搜索结果/影视站链接没反应。
