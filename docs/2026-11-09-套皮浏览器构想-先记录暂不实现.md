# MyCast 套皮浏览器构想（先记录，暂不实现）

> **决策**：2026-11-09 用户提出"把项目改得像套皮浏览器"，但判断**先不做**，仅记录构想。
> 触发时机：等搜索→真实页渲染链路稳定 + 用户明确要求浏览功能后再做。

## 一、构想一句话

把 MyCast 的主窗口从"只显示自家 UI"升级成**套皮浏览器**——用户能在 MyCast 里像用手机浏览器一样自由浏览，但**默认手机 UA**，且**保留 MyCast 自己的搜索/投屏能力**。

## 二、为什么用户会想要（动机）

当前痛点：点击搜索结果 → 主窗口直接 `location.href` 导航到目标站（`v0.13.3` 已实现），但：

1. **回不来**：主窗口变成目标站页面后，MyCast 自己的 UI（搜索/媒体库/投屏）就没了，用户要手动输 `http://127.0.0.1:18080/ui` 才能回。
2. **没有 URL 栏**：用户在盗版站里跳转（点"下一集"、点站内链接）后，看不到/改不了地址。
3. **没有前进后退**：只能在目标站里往前点，回退靠浏览器手势/快捷键，体验割裂。

套皮浏览器 = 给主窗口套上"浏览器 chrome"（URL 栏 + 前进后退 + 刷新 + 手机 UA），让用户自由逛盗版站，同时一键回 MyCast。

## 三、方案要点

| 需求 | 实现方向 |
|---|---|
| **URL 栏** | 主窗口顶部加输入框，显示当前 URL，可编辑回车导航 |
| **前进/后退/刷新** | 调用 wails3 WebView 的 `GoBack()`/`GoForward()`/`Reload()` |
| **默认手机 UA** | wails3 WebView 设 mobile UA（`Mozilla/5.0 (Linux; Android 13; SM-S9180)...`），盗版站按手机版返回 |
| **回到 MyCast** | 一键导航回 `http://127.0.0.1:18080/ui` |
| **浏览器模式开关** | MyCast UI 里有"浏览器模式"入口；浏览模式里顶部有"回 MyCast"按钮 |

## 四、依赖 / 改动面

- **wails3 壳**（`wails3/main.go`）：
  - 主窗口 `WebviewWindowOptions` 加 UA 设置（或 per-request）
  - 监听导航事件（`OnNavigation`）更新 URL 栏
  - 暴露 GoBack/GoForward/Reload 给前端 JS 桥
- **前端**（`index.html`）：顶部加浏览器 chrome 条（URL 输入框 + 前进/后退/刷新 + 回 MyCast）
- **后端**：基本不动（浏览是纯前端壳层行为）

## 五、为什么"好像不做也可以"

1. **核心闭环不依赖它**：搜剧 → 点结果 → 看真实页 → 点集数 → 投屏，`v0.13.3` 已经通了。套皮浏览器只是**提升浏览体验**（能自由逛、能回退），不是闭环必需。
2. **有替代方案**：目标站里点"下一集/站内链接"本来就是页面内跳转（能看）；回 MyCast 用地址栏输 `18080/ui`（凑合）；前进后退用键盘 `Alt+←/→`（桌面）或 WebView 手势（Android）。
3. **成本**：要动 wails3 主窗口导航 + UA + 事件监听，改动面不小，容易引入新的 WebView 崩溃风险（项目已有 WebKitGTK 崩溃史，见 `2026-11-08-WebKitGTK渲染崩溃` 文档）。

## 六、什么时候值得做（触发条件）

- [ ] 用户明确反馈"回 MyCast 不方便 / 想看 URL / 想后退"（需求真实出现）
- [ ] 搜索 → 真实页 → 集数 → 投屏链路稳定一段时间无回归
- [ ] 有完整时间做 wails3 壳改造 + 回归测试（含 WebKitGTK 崩溃回归）

## 七、不做的影响（可接受）

- 逛盗版站时**回 MyCast 要手动输地址**（或重启 App）
- **无前进后退**，靠浏览器手势/快捷键凑合
- **看不到当前 URL**（地址栏）
- 但**核心投屏闭环不受影响**

## 八、结论

**先不做，记录在案。** 当前优先级低——核心闭环已通，套皮浏览器是"锦上添花"，等用户真实需求出现再做。
